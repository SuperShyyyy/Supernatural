# Phase 0 — Editor Layout / Zoom Prototype 验证清单

启动：`npm run dev` → http://127.0.0.1:5173

页面右侧 **布局审计 HUD** 是本次验证的核心：它把"任何元素都不能把横向滚动抛给上层"
变成实时断言。全绿 = PASS；只要 `html / body / .app / .editor-viewport / .editor-content`
任意一层出现横向溢出，或内容列里出现比列宽更宽的元素，就会变红并列出越界元素。

## 对照需求 18 项

| # | 验证项 | 怎么验 | 期望 |
|---|---|---|---|
| 1 | 编辑区域居中 | 任意宽度下观察内容列 | 始终水平居中 |
| 2 | 最大内容宽度 | 宽窗口 + 100% | 列宽 = `46em`（736px @16px），不随窗口继续变宽 |
| 3 | 最小内容宽度 | 模拟视口拖到 320px | 列宽 = 容器宽度 - 2×gutter，不出现横向滚动 |
| 4 | viewport resize | 拖"模拟视口"滑块 / 拖真实窗口 | 列宽连续变化，HUD 全程 PASS |
| 5–12 | 100 / 110 / 125 / 150 / 175 / 200 / 250 / 300% | 下拉框或 Ctrl/Cmd + +/− | 文字与列宽等比放大；超过视口后列宽被钉死，**字符数变少但不溢出** |
| 13 | 窗口缩小 | 滑块拖到 320–600px | 图片收缩、表格内部滚动、代码块内部滚动，页面无横向滚动条 |
| 14 | 窗口放大 | 滑块拖回最大 | 列宽回到 46em 上限并重新居中 |
| 15 | 超长文本 | 第 1 节 `md-long-token` | 自动换行 / 断字，不顶宽 |
| 16 | 超宽图片 | 4000×900 图 + 手动放大到 2400px 的图 | `max-inline-size:100%` 等比收缩，不产生滚动条 |
| 17 | 超宽表格 | 18 列 × 8 行 | 先自动适配并换行；min-content 仍过宽时在表格内部横向滚动 |
| 18 | 超长代码块 | 160+ 字符长行 | 只在代码块内部横向滚动，普通文本宽度不受影响 |

补充：`Ctrl/Cmd + 0` 重置 100%；Dark 按钮切换主题；"+5000 段落"用于快速滚动与大文档体感。

## 结论要点

- 宽度只能**自顶向下**传：Viewport → Editor Viewport → Content Column → Block。
- 溢出必须在**产生它的那一层**消化：文本换行 / 图片收缩 / 代码与表格内部滚动。
- 因此"放大后整个页面比屏幕还大"在结构上不可能发生：
  内容列宽度是 `min(理想 em 宽度, 100%)`，`100%` 是容器内容盒的硬上限。
